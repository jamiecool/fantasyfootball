# 2026-09-01 — folding the second league into the build

## What this was

A Cowork session had already built the two-league report and left it as
`cleandata/draft2026.html` plus a `twoleague/` source folder. The job today was to
take that as the **spec** and rebuild it as a real part of the pipeline, because the
way it was made could not survive `build_all.py`.

## Why the Cowork version had to be redone

It was a **patch-on-artifact** pipeline:

    report_v2.html (= build_dashboard.py OUTPUT)
      + patch1.py   markup: league selector, tabs, PPP panels, CSS
      + patch2.py   JS: league state, PPP renderers, snake planner
      + patch3.py   JS/markup: post-draft roster sub-view (both leagues)
      = draft2026.html

Three scripts string-replacing the generated 4MB HTML, each raising
`ANCHOR NOT FOUND` if the markup moved. Nothing was wired into `build_all.py`, and
`report_v2.html` was not even kept, so the chain could not be re-run as shipped. Now
trap 11 in `CLAUDE.md`.

## The move that made this cheap

**Every anchor those patches matched lives in `dashboard_template.html`, not in the
injected data.** So instead of hand-transcribing ~800 lines of JS — and inventing new
bugs doing it — the same three patches were replayed once against the *template*. Two
changes on the way through:

- `const D2 = {…197KB of json…}` became `const PPP = D.ppp`, so the data arrives through
  the existing `__DATA__` blob like every other dataset. A template must not carry data.
- `D2` renamed to `PPP` throughout (22 sites). Fine as a throwaway in generated output,
  not fine as a name someone has to read.

**Verification was an equivalence check, not an opinion.** The patch chain was first run
against a fresh build to confirm it reproduced the checked-in `draft2026.html` — it did,
differing only by a Hub-injected CSP tag. Then the new build's output was diffed against
that reference with the two data payloads blanked. The diff came back as *exactly* the
four intentional changes and nothing else; every renderer byte-identical.

## What was built

| | |
|---|---|
| `build_ppp_data.py` | new pipeline stage, `rawdata/ppp/` → `cleandata/analysis/ppp_data.json`. Verified byte-identical output to the Cowork script |
| `rawdata/ppp/` | the ESPN PSVs moved out of `twoleague/`, plus a README on provenance and the two gaps |

## Two bugs fixed that the spec had

**`xplans` never reached disk.** The Cowork README flagged it: `serve.py`'s
`write_state()` knew three keys, so Perennial Push draft plans lived in `localStorage`
and never left the browser that made them. Now posted, validated, persisted and baked
back in — round-trip tested browser → `serve.py` → `board_state.json` →
`build_dashboard.py` → page.

**A build with no `ppp_data.json` threw and took the PBAFFL board down with it.** A
fresh clone that has not run `build_ppp_data.py` now gets a working single-league page:
the switcher and PPP tabs are removed and a stale `localStorage` preference for `ppp` is
ignored. Caught only by building the no-PPP variant and loading it — the first attempt at
this guard missed a top-level `PPP.board.forEach` because the grep used to find such
references was wrong (`^[a-zA-Z(]` ate the leading `P`). Worth remembering: verify the
degraded path by *building* it, not by reading the code.

## The unrelated thing that blocked everything

`build_all.py` died at its first stage. **`build_clean_data.py` has not parsed since
commit `390eb34` (2026-08-17)** — the player_bio block was pasted twice and one copy had
a real newline inside an f-string. Nobody noticed for two weeks because the database
already existed, so every later session only rebuilt the dashboard.

Fixed: dropped the duplicate block, and repaired a mangled `_ours` line in the survivor
(two expressions collided on one line; the `pd.read_sql` half was dead by construction —
`con` is not created until 150 lines further down). `player_bio` rebuilds to 1,701 rows,
100% with height. Now trap 12.

`build_all.py` passes end to end in 91s.

## Left alone deliberately

**`fetch_espn_league.py` appeared mid-session** (09:35) from a concurrent session, along
with a `.gitignore` line for `espn_credentials.json`. It is a good fetcher, but it writes
`rawdata/espn/*.csv` on a different naming scheme to the `rawdata/ppp/*.psv` this build
reads, and **it has never been run** — `rawdata/espn/` does not exist. Rather than guess
at a schema no file demonstrates, the build was finished against the data that exists.
Reconciling the two layouts is a real task and it is written up in `notes/backlog.md`.

# Same day, part 2 — the board was ranked the wrong way

Jamie, on being shown how the PPP board worked: *"so you used projections?"* and then
*"we've already been through this with rankings for the yahoo league... what we decided
the best way was to use the underdog adp for player rankings and then to weight that
based on the last 3 year average of where each position was drafted for that league."*

He was right, and this was not a subtle miss. `CLAUDE.md` has a section headed **"How
the 2026 board is priced (settled 2026-08-10)"**, and I had read it at the start of the
session. I still shipped a board ranked on ESPN projections — and then explained that
method back to him as if it were the design.

## Why it happened, so it does not again

The section was written for PBAFFL and **read as PBAFFL-only**. The second league
arrived with a projection-based board already built by the Cowork session, and I treated
"fold this into the build" as a packaging job rather than asking whether what I was
packaging agreed with the repo's own settled method. It did not.

The section is now retitled *"How a board is priced — EVERY LEAGUE, not just PBAFFL"*
with a table showing how the two halves map onto an auction and a snake draft. Trap 13.

## What the board does now

| half | source |
|---|---|
| ordering **within** a position | Underdog ADP — 206 of 249 players |
| ordering for K / DEF | ESPN's own ADP — Underdog carries neither (trap 8) |
| weighting **across** positions | **this league's own 2023–25 drafts**: the overall pick the Nth-best at each position actually went |
| projections | `Proj` column, never the sort |

New module `ppp_board.py` holds it. The cross-position curve is the direct analogue of
PBAFFL's price curve — "what pick does WR9 go at here" instead of "what does WR9 cost
here" — and it is strictly better than what it replaced, because **it is the only thing
in the board that knows the league is superflex, and it knows it by measurement.** The
old version asserted a starter requirement of QB = 2.0 per team and derived value from
it. The history just says: QB1 goes at overall pick 2 here, QB5 at 10, RB5 at 20.

Sanity check that lands well: the new board puts **13 QBs inside rounds 1–3**, and the
room itself has taken **13.4** by that point across five seasons. The old projection
board said 15.

## The smoothing question, which nearly shipped a real error

First cut copied PBAFFL's curve treatment — smooth, then `IsotonicRegression` (trap 9
forbids `np.maximum.accumulate`). The smoothing was wrong here and the output showed it:
**RB1 landed at pick 6.5 when the measured median is 2**, and TE1 at 40 against a real
31. A centred 3-wide mean has no left neighbour at rank 1, so it averaged the first
player at a position with the second, on the steepest part of the curve.

Tested three variants rather than guessing. The answer is structural: **position rank is
defined by draft order within a season**, so pick-by-rank is strictly increasing inside
every season and the median across seasons inherits it. Measured 4 inversions across 224
position-ranks, every one in a tail cell with n<3 where a season did not draft that deep.
So isotonic alone is exactly right — it repairs those four cells and is a no-op elsewhere
— and pre-smoothing only adds bias. What I had called "roughness" was the curve's genuine
convexity, not noise.

## Also corrected: the name-join gap I had written up as real

The Cowork README claimed ~18 players were spelled differently from Underdog, and I
repeated it in `rawdata/ppp/README.md` and the backlog without checking. Measured:
**0 collisions**, 206/249 joined, and **3** unmatched skill players (Najee Harris,
Darius Slayton, Jahan Dotson — all deep-round names Underdog does not rank). The repo's
own `player_key` already folds `Jr/III` and punctuation and carries an alias table.
`build_board()` now raises rather than joining if a collision ever appears (trap 1).

Backlog closed as item 3; two honest new assumptions added as items 5 and 6.

## Where projections still legitimately appear

Not everything projection-shaped had to go. The Draft plan tab uses `exp` to total a
roster's starting points and to decide which of *your own* players fills each slot.
That is roster evaluation, not ranking, and there is no market answer to "how good is
this hypothetical eleven" — so it stays, labelled as such on the page.

# Same day, part 3 — a general draft plan, and a documentation miss

Jamie asked for a general draft plan for Perennial Push — no player names, just the shape
of the draft. Built it, published it as a page, and he asked how many seasons it rested
on. Then: *"did you update the doc for this?"*

**No, I had not.** The page was updated; the repo was not. That is exactly the failure
`notes/findings/` exists to prevent — an analysis living only in a chat window and a URL,
with its scripts sitting in an untracked scratch directory I was about to delete. Same
species of mistake as part 2: treating the repo's conventions as background rather than
as the thing that makes work survive.

Now written up properly:

| | |
|---|---|
| `analyze_ppp_shape.py` | the reproducible evidence, three questions, all splits print their n |
| `notes/findings/ppp-draft-shape.md` | PPP-1..PPP-4 plus a "did not show up" list |
| `notes/findings/README.md` | a section separating the two leagues' numbering |
| `CLAUDE.md` | pointer in the second-league section |

## Why PPP findings are numbered PPP-1, not 12

PBAFFL's run 1–11. Continuing that sequence would have invited exactly the crossover
`CLAUDE.md` warns about — a PPP finding quoted in an auction argument. Separate namespace
makes it impossible to do by accident.

## The season-window question was a real catch

The plan mixed two windows and the page claimed one. Round-band rates, quarterback
figures and outcome splits are **five seasons** (2021–25, 62 team-seasons, 1,116 picks).
The full-PPR receiver spread was **three** — and only because I had matched it to the
board's pick-curve window out of habit.

That was the wrong instinct in a specific way worth remembering: the pick curve is
deliberately short *because draft behaviour goes stale*, while a fact about NFL scoring
has the opposite requirement and wants every season available. Recomputed on all nine
(2017–25) and checked for window sensitivity — WR widens +28.0 / +26.2 / +26.4 on 3 / 6 /
9 seasons, so the conclusion never depended on the choice. The page and the finding both
state their window inline now.

## The finding worth remembering

**Leave QB2 past round 9 and the season is gone** — 4.75 wins and a 9.75 finish against
7.33 and 6.28. Thin at n=8, so it is only stated that strongly because two independent
lines agree: 23.6 of the 24 startable quarterbacks are gone by the end of round 8, and
QBs taken in rounds 7–12 beat the skill players taken alongside them by +52 to +62.

The corollary is the part that contradicts received wisdom: taking two quarterbacks in
rounds 1–3 was worth **−0.53 wins**. The rule is *by round 8*, not *early*.
